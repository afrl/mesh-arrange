# MeshArrange Examples, `.vtu` Mesh Exports & Gallery Generator

This directory contains five self-contained C++17 demonstration programs showcasing the core capabilities of **MeshArrange**. Each executable directly outputs standard VTK XML UnstructuredGrid (`.vtu`) meshes (requiring no external VTK dependency) for interactive inspection in **ParaView**, **PyVista**, or **Gmsh**. Pre-generated `.vtu` outputs for every example are stored in [`../docs/meshes/`](../docs/meshes/).

## Demo Programs & Downloadable `.vtu` Outputs

| Executable | Source | Saved `.vtu` Meshes (`docs/meshes/`) | Demonstrated Capability |
| :--- | :--- | :--- | :--- |
| `demo_brep_arrangement` | [`demo_brep_arrangement.cpp`](demo_brep_arrangement.cpp) | `demo1_brep_arrangement_{inputs,brep,volumes}.vtu` | Exact (`CGAL::Epeck`) surface arrangement of an icosphere and tilted torus (`remove_overlaps = false`) extracting `BRepVolume`, `BRepFace`, `BRepCurve`, and `BRepVertex` topology. |
| `demo_priority_clipping` | [`demo_priority_clipping.cpp`](demo_priority_clipping.cpp) | `demo2_priority_clipping_{inputs,brep,volumes}.vtu` | Single-pass boolean RVE assembly combining `SOLID` inclusions (`priority = +2`), a `SOLID` matrix (`priority = 0`), a `CLIP_INSIDE` cylindrical bore (`priority = +5`), and a `CLIP_OUTSIDE` unit-cell cutter (`priority = +5`). |
| `demo_harmonic_medial` | [`demo_harmonic_medial.cpp`](demo_harmonic_medial.cpp) | `demo3_harmonic_medial_{inputs,before_volumes,brep,volumes}.vtu` | Pairwise (`K = 2`) harmonic medial interpenetration removal on crossing sinusoidal composite tows, generating a smooth doubly-curved saddle contact interface. |
| `demo_multiway_junction` | [`demo_multiway_junction.cpp`](demo_multiway_junction.cpp) | `demo4_multiway_junction_{inputs,before_volumes,brep,volumes}.vtu` | Simultaneous multi-material (`K = 4`) overlap partitioning on a tetrahedral cluster of four overlapping spheres, resolving 15 raw subregions into 4 watertight cells meeting at a central quadruple `BRepVertex`. |
| `demo_gmsh_rve_workflow` | [`demo_gmsh_rve_workflow.cpp`](demo_gmsh_rve_workflow.cpp) | `demo5_gmsh_rve_{inputs,brep,volumes,gmsh3d}.vtu` | End-to-end woven composite RVE arrangement exported as a discrete B-Rep (`GVertex`, `GEdge`, `GFace`, `GRegion`) and meshed into conforming 3D tetrahedra with Gmsh. |

## Inspecting `.vtu` Meshes in ParaView / PyVista

Each demonstration writes three primary `.vtu` files (plus `_before_volumes.vtu` for overlap-removal demos and `_gmsh3d.vtu` for the Gmsh 3D RVE demo):

- **`<stem>_inputs.vtu`** (`VTK_TRIANGLE` cells):
  - `InputObjectID` — 0-based index of the input `InputSurface`.
  - `ObjectType` — `0 = SOLID`, `1 = CLIP_INSIDE`, `2 = CLIP_OUTSIDE`.
  - `Priority` — Integer boolean priority assigned to the surface.
  - `InputFacetID` — Provenance CAD facet tag on the input surface.
- **`<stem>_brep.vtu`** (`VTK_TRIANGLE` faces + `VTK_LINE` curves + `VTK_VERTEX` corners sharing `ArrangeResult::surface_mesh.vertices`):
  - `EntityDim` — Topological dimension (`2` = `BRepFace`, `1` = `BRepCurve`, `0` = `BRepVertex`). Use ParaView's *Threshold* filter on `EntityDim` to isolate surfaces, seam curves, or corner vertices.
  - `EntityTag` — Entity ID within `brep_faces`, `brep_curves`, or `brep_vertices`.
  - `BoundedRegionA`, `BoundedRegionB` — Pair of 3D `RegionID`s separated by each `BRepFace` (`-1` on the exterior boundary).
  - `OwnerObjectID` — Source solid `object_id` on single-owner faces (`-1` on shared interfaces/seams).
  - `IsMedialSheet` — `1` on newly synthesized harmonic medial contact sheets, `0` otherwise.
  - `Valence` — Number of bounded regions (`BRepFace`), incident faces (`BRepCurve`; `>= 3` on non-manifold junctions), or incident curves (`BRepVertex`).
- **`<stem>_volumes.vtu`** / **`<stem>_before_volumes.vtu`** (`VTK_TETRA` cells):
  - `BRepVolumeID` — 0-based `RegionID` in `ArrangeResult::brep_volumes`.
  - `OwnerObjectID` — Owning solid `object_id` (`-1` when `NumOwners > 1`).
  - `NumOwners` — Multiplicity $K$ of overlapping input solids occupying the region.
  - `IsOverlap` — `1` if `NumOwners > 1` (present when `remove_overlaps = false`), `0` if disjoint.
- **`demo5_gmsh_rve_gmsh3d.vtu`** (`VTK_TETRA` cells):
  - Conforming multi-material 3D tetrahedral mesh generated by Gmsh from the populated discrete `GModel` (`BRepVolumeID`, `OwnerObjectID`, `IsResin`).

## Building & Running the Demos

From the repository root:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DMESHARRANGE_BUILD_EXAMPLES=ON
cmake --build build -j

# Export .vtu meshes into docs/meshes/ (and optional JSON bundles into build/demo_json/)
mkdir -p docs/meshes build/demo_json
./build/examples/demo_brep_arrangement  docs/meshes build/demo_json/demo1.json
./build/examples/demo_priority_clipping docs/meshes build/demo_json/demo2.json
./build/examples/demo_harmonic_medial   docs/meshes build/demo_json/demo3.json
./build/examples/demo_multiway_junction docs/meshes build/demo_json/demo4.json
./build/examples/demo_gmsh_rve_workflow docs/meshes build/demo_json/demo5.json
```

Running any executable with no arguments (`./build/examples/demo_brep_arrangement`) writes its `.vtu` files into the current working directory.

## Regenerating the Gallery Figures & Gmsh 3D Volume Mesh

With a Python virtual environment containing `numpy`, `matplotlib`, `pillow`, `pyvista`, and `gmsh`:

```bash
python3 examples/render_gallery.py build/demo_json docs/images docs/meshes
```
